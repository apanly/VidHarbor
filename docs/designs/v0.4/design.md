# VidHarbor v0.4 技术设计

## 1. 整体方案概述

在现有 Express/EJS 单页面体系内增加一条固定、严格的双语渲染链：服务端用 Node.js 原生能力从请求的 `vidharbor_language` Cookie 中只接受 `zh-CN` 或 `en`，其余情况统一选择 `zh-CN`；一份服务端维护的扁平翻译目录同时供 EJS 直接取值并以安全 JSON 内嵌到当前 HTML，浏览器端公共模块只读取该服务端已选目录，负责严格翻译查找、错误展示和原生 `Intl` 格式化。语言按钮直接写同一路径可见的会话 Cookie 并刷新当前 URL，因此不增加路由、API、数据库字段、构建依赖或第二套模板，也不会改变页面之外的业务调用。两份 README 在启动时分别校验并预渲染，`/guide` 仅按当前语言从固定映射中选择；自动化测试在目录、Cookie、10 个页面、动态状态、日期数字、README 和既有 API 契约各边界上失败优先，最终再以隔离浏览器逐页留存验收记录。

## 5. 关键技术决策

### 5.1 一份翻译事实源同时服务 EJS 和浏览器，而不是两套目录

翻译目录以扁平、字面量键维护在 `src/i18n.ts`，`zh-CN` 是基准键集合，`en` 在 TypeScript 编译期受同一键类型约束，启动/测试再比较完整键集合并检查非空字符串。页面请求只选择其中一个目录：EJS 的 `t` 与内嵌给浏览器的 JSON 来自同一个对象，避免服务端首屏与动态区域分别维护文案或选择出不同语言。

浏览器端 `t` 不接受默认值，也不回退到中文、英文、键名或空字符串。状态映射只把当前已存在的枚举值映射到字面量翻译键，不动态拼接键；因此静态测试可以核对每个调用，运行时遇到未知状态也能显式失败。目录只承载应用自有文案，不收录 README 正文、用户数据、第三方内容、URL、路径、SQL、平台名和协议标识。

### 5.2 用页面 Cookie 和原地刷新，而不是新增设置 API

语言不属于业务数据，服务端没有设置接口、账号或数据库写入需求。浏览器按钮直接写大小写精确的 `vidharbor_language=zh-CN` 或 `vidharbor_language=en`，属性固定为 `Path=/; SameSite=Lax`；不设置 `HttpOnly` 是因为浏览器端需要写入，不设置 `Secure` 是为了保持当前受信内网 HTTP 部署可用，不设置 `Max-Age`/`Expires` 是因为已确认的持久化范围只有刷新和同一浏览器会话内跨页面导航。若未来明确要求浏览器重启后保留，再单独确认有效期后增加持久过期属性。

服务端只解析这一个名称的 Cookie，并对最终值做精确白名单判断；缺失、空值、大小写变体、地区变体、编码猜测或其他任意值均走 `zh-CN`。不读取 `Accept-Language`、浏览器设置、时区、用户代理或 IP。切换后调用当前文档的 `location.reload()`，不构造目标路由，因此 pathname、query 和 hash 原样保留，频道详情和预览 ID 不丢失，也不会跳转总览或触发 API 写操作。

### 5.3 目录以内嵌安全 JSON交给浏览器，而不是额外请求或全局脚本复制

每个完整 HTML 文档内嵌当前语言及其目录的 `application/json` 数据，序列化时至少转义 `<`、U+2028 和 U+2029，防止翻译内容提前结束脚本元素；浏览器模块同时校验该语言与 `<html lang>` 一致。这样动态文案无需翻译服务、静态 JSON 请求或第二份 JavaScript 文案表，页面刷新后的 HTML、动态脚本和格式化器天然处于同一语言。

EJS 中普通翻译继续使用转义输出；README 是经过既有 `marked` 管线生成的受控文档 HTML，仍只在 `guide.ejs` 的固定位置使用非转义输出。含用户标题、名称、路径或第三方错误的翻译参数在浏览器只通过 `textContent` 或安全属性赋值落入 DOM，不允许把插值结果交给 `innerHTML`。

### 5.4 用原生 `Intl` 统一日期和可读数字，不改业务值

时间格式化器以当前语言和固定 `Asia/Shanghai` 创建 `Intl.DateTimeFormat`；输入仍是既有时间戳，排序与 API 值不变，无效日期仍返回原值。可读计数、分页摘要和文件大小使用当前语言的 `Intl.NumberFormat`，文件大小仍按 1024 进位并保持既有单位及最多两位小数。

任务 ID、频道 ID、下载 ID、SQL、URL、路径、数据库结果、表单提交值和 API 数值不进入数字格式化。固定时长和 `HH:MM:SS` 输入继续使用既有补零算法；发布日期等当前作为业务字符串返回的字段不擅自重解释为时间戳。

### 5.5 页面错误本地化停在展示层，不改 API

API 继续返回既有英文 `{ error: { code, message } }`、HTTP 状态和字段。公共浏览器模块为 `src/errors.ts` 中每个当前错误码提供本地化应用框架；固定的应用自有消息使用已确认的精确映射，yt-dlp/平台/网络产生且已脱敏的动态详情只在本地化框架后保持原文。原生 `Error` 同样只翻译“加载/操作失败”等框架，不机器翻译其详情。

未知错误码、缺字段的错误对象和未知状态不显示原始枚举或猜测文案，而是抛出开发错误，由自动化测试暴露。该规则不吞掉现有第三方失败详情，也不改变服务端脱敏位置、同源校验或错误响应。

### 5.6 两份 README 固定映射并在启动边界一起校验

`zh-CN` 只映射仓库根目录的 `README.md`，`en` 只映射 `README.en.md`。路由初始化时读取两份固定路径，分别要求唯一有效的 `APP_GUIDE_EXCLUDE_START`/`APP_GUIDE_EXCLUDE_END` 顺序，删除排除段后各自调用 `marked.parse` 并缓存；请求阶段只以已验证语言索引缓存，不读取文件、不翻译 HTML，也不使用 Cookie 拼路径。任一文件损坏都会阻止页面路由建立，不能只让对应语言在运行时静默失败。

### 5.7 自动化证明固定契约，浏览器验收覆盖真实交互

单元测试负责可穷举边界：两个语言值、目录键集合、状态枚举、翻译调用、固定格式输入和无效输入。HTTP 页面测试对 10 个 GET 路由分别验证两种语言与默认路径，并用 Cookie/请求头组合证明不存在语言协商；受控脚本 DOM 证明切换写入值和原地刷新。API 回归测试只增加 Cookie 维度，不改现有业务夹具。

隔离浏览器验收使用本地数据库与现有 API/fixture 构造频道详情、下载预览、空列表、成功、失败和确认场景；不访问真实 YouTube/Bilibili 等平台，不上传敏感 Cookie，不执行永久删除。证据文件中未实际执行的项只能记为阻塞或排除，不能标记通过。

### 5.8 不可逾越的边界

- 语言集合固定为 `zh-CN`、`en`，默认值唯一为 `zh-CN`；不增加第三种语言、别名、模糊匹配、自动发现或多级回退。
- 保留每个现有 EJS 页面一份模板及全部现有页面/API 路由；不新增语言路由、语言 API、请求字段、响应字段、SSE 事件或状态值。
- 不修改 SQLite schema、迁移、服务层、下载/频道/提醒/授权/代理/数据库业务规则，也不让语言切换提交或重放写请求。
- 不增加 i18n、Cookie、日期或测试依赖；只使用 Node.js、EJS、浏览器 DOM、`Intl` 和现有 Vitest。
- 用户输入、数据库值、第三方平台内容和失败详情不进入翻译目录；专有名称与技术标识按原内容显示。

## 6. 风险与注意事项

- **翻译覆盖面大**：当前应用文案分散在 10 个 EJS、12 个动态/共享脚本及响应状态映射中。迁移必须以“字面量键扫描 + 两语言页面断言 + 动态 fixture”三层检查收口；不能只替换可见标题而遗漏 `aria-label`、确认框、移动端 `data-label`、空状态或异常分支。
- **严格失败与用户可见错误要分层**：翻译键、状态、错误码缺失属于开发错误，应在测试和运行时抛出；用户/第三方详情属于业务内容，应保留在已翻译的安全框架内。不能为了页面不报错而显示键名、原始状态或另一语言。
- **Cookie 只能用于选择**：原始 Cookie 值在白名单判断前不得写入 HTML、日志、文件路径或模块路径。语言 Cookie 与授权管理的 Netscape Cookie 文件完全无关，也不能因同名“Cookie”概念复用服务或存储。
- **切换不得丢上下文**：实现不得用 `location.href = '/'`、固定路由链接或删除 query 的 URL 重建方式。自动化和验收必须使用 `/channels/:id`、`/downloads/preview?id=...` 及带分页/筛选 query 的页面证明原地刷新。
- **容器文件完整性**：本地源码环境天然存在两份 README，但运行镜像当前只复制中文文件；Dockerfile 漏复制 `README.en.md` 会导致页面路由初始化失败。干净构建测试、Docker 构建和验收启动均要覆盖该差异。
- **`Intl` 输出依赖运行时 locale 数据**：项目固定 Node 24 和现代浏览器，测试应断言项目选定的固定输入输出并保持 `Asia/Shanghai`，不能用开发机默认 locale/timezone。浏览器和 Node 的标点细节若不同，应以各自原生结果验证语义，不自行实现第二套日期算法。
- **标识与可读数字边界**：计数和文件大小要本地化，ID、时长、SQL、URL、路径、数据库原值和表单/API 数值不得改写。评审时需重点检查 `String(number)` 的用途，避免把展示数字遗漏或把业务标识误格式化。
- **README 内容不等于翻译目录**：中英文文档必须人工保持能力与边界一致，目录键一致性测试不能替代文档对照；排除标记在两份文件中都必须保留且顺序正确。
- **现有页面测试与源码结构耦合**：`pages.test.ts` 当前会截取脚本并用受控 DOM 执行。迁移公共 i18n import 时应同步测试装载方式，继续验证行为而不是仅断言源码字符串；不得为测试引入浏览器框架或生产兼容层。
- **验收数据必须本地可控**：频道详情、下载预览、状态、分页和失败场景用临时 SQLite、现有 fake yt-dlp/ffmpeg 或直接 API fixture 构造。真实外部平台、敏感 Cookie 原文和永久删除是明确排除项，其余本地场景不得借此跳过。
