## [v0.4] 建立中英文界面的最小国际化基础

- 描述：让 VidHarbor 仅支持 `zh-CN` 与 `en` 两种界面语言，默认中文，通过页面入口切换并使用 Cookie 持久化；未知或缺失语言值回到中文，服务端页面与浏览器端动态文案共用已确认的翻译键，不复制页面、不增加第三方国际化依赖。
- issue整理:
  - 做什么：为服务端渲染和浏览器端 JavaScript 建立中英文翻译能力，设置中文 / English 切换入口并持久化当前语言。
  - 边界：只接受 `zh-CN` 和 `en`，默认固定为 `zh-CN`，不根据浏览器语言自动选择，不为第三种语言预留框架。
  - 最终决策：清除 Cookie、缺少 Cookie 或 Cookie 值无效时显示中文；切换后刷新和跨页面导航保持选择，页面不得显示缺失翻译键。
- 来源: Gitea #17

## [v0.4] 完成全部 Web 页面的中英文文案覆盖

- 描述：覆盖总览、下载、频道、频道详情、提醒、授权管理、配置、数据库、系统说明和下载预览的 EJS 静态文案及浏览器端动态文案，并让日期与数字按当前语言格式化；中文行为保持不变，英文系统说明读取现有 `README.en.md`。
- issue整理:
  - 做什么：翻译所有应用自有的页面标题、导航、按钮、状态、空状态、确认文本和可展示错误，并支持对应语言的系统说明与日期数字格式。
  - 边界：不翻译用户输入、频道名、视频标题、路径、SQL 或第三方平台内容；不改变 API 字段、状态值、错误码和路由契约；不维护两套 EJS 页面。
  - 最终决策：两种语言逐页均不得出现应用自有文案混用，切换语言后留在当前功能页面，中文现有业务流程不得回归。
- 来源: Gitea #18

## [v0.4] 补齐双语测试、文档与 Web 验收

- 描述：为中英文支持补齐默认中文、语言持久化、未知语言拒绝、双语系统说明、动态状态错误和日期格式的自动化测试，并更新双语 README、Changelog 与逐页 Web 验收证据。
- issue整理:
  - 做什么：增加最小自动化边界测试，更新用户文档，并使用隔离浏览器分别验收全部可发现页面的中文和英文状态。
  - 边界：真实外部平台、敏感 Cookie 和永久删除按既定验收排除项记录；不增加第三方国际化依赖或与两种语言无关的抽象。
  - 最终决策：测试和构建必须通过，中文和英文逐页验收必须通过或明确记录既定阻塞与排除项，未知语言值必须回到中文。
- 来源: Gitea #19
