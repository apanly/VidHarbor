# VidHarbor v0.4 产品需求文档

## 功能概述

VidHarbor v0.4 为现有单套 Web 界面建立仅支持 `zh-CN` 与 `en` 的最小国际化能力：默认使用中文，用户可从页面入口切换语言并通过 Cookie 在刷新和跨页面导航后保持选择；总览、下载、频道、频道详情、提醒、授权管理、配置、数据库、系统说明和下载预览的服务端静态文案与浏览器端动态文案必须完整覆盖两种语言，日期和数字按当前语言展示，同时保持现有业务流程、路由和 API 契约不变。本版还补齐双语自动化测试、README、Changelog 及逐页 Web 验收证据，不引入第三方国际化依赖、第三种语言能力或第二套 EJS 页面。

## 用户故事

1. 作为中文用户，我希望首次访问、清除语言 Cookie 后访问或携带无效语言值访问时始终看到完整中文界面，不受浏览器首选语言影响。
2. 作为英文用户，我希望从当前页面切换到 English 后仍停留在同一功能页面，并在刷新或进入其他页面时继续看到完整英文界面。
3. 作为任一语言的用户，我希望页面标题、导航、表单、状态、空状态、确认提示、错误和辅助功能标签使用同一种当前语言，且日期与数字符合该语言的展示习惯。
4. 作为系统说明的读者，我希望中文界面读取 `README.md`，英文界面读取 `README.en.md`，并在切换语言后继续停留在系统说明页面阅读对应内容。
5. 作为现有 VidHarbor 用户，我希望升级后频道、下载、提醒、授权、代理、数据库浏览等业务行为和 API 调用方式不变，用户输入与平台内容也不会被系统擅自翻译。

## 功能详细说明

### 1. 最小双语基础与语言选择

#### 1.1 固定语言契约

- 界面语言只接受大小写精确的 `zh-CN` 和 `en`；`zh-CN` 是唯一默认值。
- 缺少语言 Cookie、语言 Cookie 被清除或其值不属于上述固定集合时，服务端页面与浏览器端动态文案均必须使用 `zh-CN`。
- 无效值不得被猜测、截断或映射为其他语言。例如不得根据相似值推断 `zh-CN` 或 `en`，也不得因无效 Cookie 返回页面错误。
- 不读取或使用浏览器语言、`Accept-Language`、时区、操作系统设置或其他请求信息自动选择语言。
- 本版不支持第三种语言、地区变体、自动协商、用户账户语言设置或多级语言回退。

#### 1.2 切换与持久化

- 使用共享页面外壳的页面必须提供明确的“中文 / English”切换入口，并让用户能够识别当前语言。
- 用户选择 `zh-CN` 或 `en` 后，系统必须把该精确值写入语言 Cookie，并刷新当前页面以同时更新服务端渲染内容和浏览器端动态内容。
- 切换不得把用户带回总览页；当前路径和查询参数必须保留。例如频道详情仍停留在同一频道，下载预览仍保留当前下载 ID。
- 有效选择必须在页面刷新及站内跨页面导航后保持。删除该 Cookie 后，下一次页面访问恢复为中文。
- 语言选择只影响界面显示，不是身份、权限或业务配置，不得写入 SQLite，也不得触发后台任务或外部平台请求。

#### 1.3 服务端与浏览器端共用翻译契约

- `zh-CN` 与 `en` 必须各有一套固定翻译目录，两个目录的翻译键集合必须完全一致；EJS 和浏览器端 JavaScript 使用同一批已确认翻译键，不得分别维护含义重复但名称不同的页面私有文案。
- 每个现有 EJS 页面只保留一份模板，通过当前语言取值；不得复制中文页和英文页，也不得新增语言专属路由。
- 浏览器端脚本必须使用服务端确定的同一当前语言，不得再次从浏览器环境推断语言。
- 页面不得显示翻译键名、`undefined`、空白占位或另一种语言作为缺失翻译的静默回退。两套目录缺键或键集合不一致属于开发错误，必须由自动化检查直接失败。
- 文档内容、用户数据或第三方内容不是翻译键，不受上述目录完整性检查约束。

#### 1.4 页面语言元数据

- 每个完整 HTML 文档的 `<html lang>` 必须等于当前语言，包括使用共享外壳的页面和独立的下载预览页。
- 浏览器标题中的页面名称必须使用当前语言；产品名 `VidHarbor` 保持不变。
- 切换入口、导航和移动端菜单的可见文字及 `aria-label` 必须与当前语言一致。

### 2. 全部 Web 页面双语覆盖与本地化显示

#### 2.1 固定页面范围

以下现有页面及其加载后的动态状态必须同时支持 `zh-CN` 和 `en`：

| 页面 | 路由 | 必须覆盖的现有内容 |
| --- | --- | --- |
| 总览 | `/` | 页面标题、提醒与下载汇总、频道检查结果、活动任务、最近已结束任务、任务类型与状态、空状态和错误 |
| 下载 | `/downloads` | 页面说明、状态页签、搜索、空状态、直下载表单、下载卡片、状态、字段标签、操作、确认文本、分页和错误 |
| 频道 | `/channels` | 列表、空状态、新增与编辑表单、授权与代理选项说明、首次同步、状态、操作、确认文本、分页和错误 |
| 频道详情 | `/channels/:id` | 频道摘要、视频与检查记录页签、筛选与批量下载、表头、下载和检查状态、空状态、分页和错误 |
| 提醒 | `/notifications` | 页面说明、列表、已读状态、单条与全部标记已读操作、空状态、分页和错误 |
| 授权管理 | `/authorizations` | 使用范围、安全说明、平台配置状态、上传与替换表单、操作、确认文本、时间和错误 |
| 配置 | `/settings` | 全局设置、代理列表与表单、帮助文案、操作、确认文本、空状态和错误 |
| 数据库 | `/database` | 页面说明、数据表区域、只读查询表单、结果摘要、空状态和错误 |
| 系统说明 | `/guide` | 页面标题、导航、快速目录及对应语言的 README 正文 |
| 下载预览 | `/downloads/preview` | 文档语言、页面标题及媒体加载、参数或播放失败时的动态错误 |

- 共享侧边栏、移动端菜单、分页组件、日期工具和 yt-dlp 任务组件属于上述页面的一部分，必须随当前语言切换。
- 所有应用自有文案必须覆盖，包括标题、导航、按钮、标签、帮助文本、占位符、表头、页签、徽标、状态、空状态、加载状态、确认文本、错误说明、分页摘要、`title` 和辅助功能标签。
- 当前中文页面中作为装饰性标题出现的英文应用文案也必须纳入翻译或移除，不能让 `zh-CN` 页面与 `en` 页面出现应用自有文案混用。
- `VidHarbor`、YouTube、Bilibili、X、Facebook、Douyin、HTTP、HTTPS、SOCKS5、SQLite、SQL、Cookie、Netscape、Chrome/Edge、文件格式、协议名及代码示例等专有名称或技术标识按内容本身保留，不因保留而视为语言混用。

#### 2.2 动态状态、确认与错误

- 当前代码已确认的下载状态、频道状态、频道检查类型与结果、通知状态、Cookie 配置状态、yt-dlp 任务类型与状态都必须按当前语言显示；底层状态值和枚举值不得改变。
- 动态创建的按钮、空状态、汇总、分页、模态框标题、删除确认和操作结果必须通过翻译键生成，不得在浏览器脚本中继续硬编码单一语言。
- 当前 API 返回的错误对象、错误码、HTTP 状态和英文消息契约保持不变。页面展示层必须为当前已确认的应用自有错误提供对应语言文案，但不得修改 API 响应以适应界面语言。
- 来自用户输入、数据库内容或第三方平台/工具的失败详情不做机器翻译；页面只翻译其应用自有字段名、引导语和错误框架，并继续遵守现有敏感信息脱敏规则。
- 遇到未确认的状态或缺失的应用翻译键时必须显式失败，不得把原始状态值、另一语言文案或猜测结果当作正常显示。

#### 2.3 日期与数字格式

- 页面中的时间戳必须按当前语言使用平台原生 `Intl` 能力格式化；`zh-CN` 使用中文格式，`en` 使用英文格式。
- 现有时间语义保持不变：时间值、排序和 `Asia/Shanghai` 展示时区不因界面语言改变。
- 应用生成的计数、分页总数和文件大小等可读数字必须按当前语言使用本地化数字格式；单位和精度语义保持现状。
- 任务 ID、频道 ID、下载 ID、URL、路径、SQL、数据库原始结果、表单提交值、API 数字字段及固定的 `HH:MM:SS` 输入/时长表达不做本地化改写，避免改变标识或输入输出契约。
- 无效日期继续沿用当前安全行为，不得因格式化失败伪造日期；两种语言必须得到一致的业务值，只允许展示格式不同。

#### 2.4 系统说明与文档来源

- `/guide` 在 `zh-CN` 下读取现有 `README.md`，在 `en` 下读取现有 `README.en.md`；不得翻译已渲染 HTML，也不得为系统说明复制 EJS 页面。
- 两份 README 都必须继续使用现有说明页排除标记，界面预览章节不得出现在系统说明页；排除标记缺失或顺序错误继续作为启动错误处理。
- 英文系统说明的目录、标题、正文和页面级控件必须为英文，中文系统说明对应内容必须为中文；代码、链接、命令、路径和产品/平台名称保持原文。
- 切换系统说明语言后仍停留在 `/guide`，并重新渲染另一份已确认 README 内容。

#### 2.5 明确不翻译和不改动的内容

- 不翻译用户输入、频道自定义名称、视频标题、代理名称、文件名、文件路径、URL、SQL、数据库查询结果或第三方平台返回内容。
- 不改变任何现有页面路由、API 路径、请求方法、请求字段、响应字段、状态值、错误码、HTTP 状态、SSE 契约或数据库结构。
- 不改变下载、频道同步与检查、提醒、授权管理、代理、设置、数据库浏览和文件操作的业务规则；语言切换不得重放写操作。
- 不新增第三方国际化依赖，不维护两套 EJS 页面，不增加第三种语言所需的插件、适配器、自动发现、嵌套回退或扩展框架。

### 3. 双语测试、文档与 Web 验收

#### 3.1 自动化测试

- 服务端页面测试必须证明：无语言 Cookie、Cookie 被清除和 Cookie 值无效时均渲染 `zh-CN`；精确的 `en` 值渲染英文；浏览器语言请求头不会覆盖上述选择。
- 持久化测试必须证明：从任一现有页面切换后保留路径和查询参数，刷新及跨页面导航仍使用所选语言，删除 Cookie 后恢复中文。
- 翻译目录测试必须证明两种语言键集合完全相同，全部现有服务端和浏览器端翻译调用都能取到非空值，页面不会渲染缺失键或静默混用另一语言。
- 页面测试必须覆盖第 2.1 节列出的 10 个页面，并验证页面标题、`<html lang>`、共享导航、关键静态文案及独立下载预览页。
- 动态测试至少覆盖当前各类状态与错误、确认文本、空状态、分页，以及总览、下载、频道详情、提醒、授权、配置和数据库脚本生成的文案。
- 日期与数字测试必须用固定输入分别断言 `zh-CN` 和 `en` 的展示结果，并证明时区和底层数值未改变；无效日期边界也必须保持现有行为。
- 系统说明测试必须证明中文读取 `README.md`、英文读取 `README.en.md`、两者均排除界面预览章节，且 README 标记损坏仍明确失败。
- 回归测试必须证明 API 响应、状态值、错误码和现有中文业务流程不变；最终完整测试和构建命令必须通过。

#### 3.2 用户文档与变更说明

- `README.md` 与 `README.en.md` 必须分别说明仅支持中文和英文、默认中文、页面切换入口、Cookie 持久化范围，以及清除或无效语言 Cookie 会恢复中文。
- 两份 README 对语言行为、页面清单和业务边界的描述必须一致，不能让任一语言文档承诺额外语言、浏览器自动选择或不同业务能力。
- `CHANGELOG.md` 必须记录 v0.4 的中英文界面、语言 Cookie、全页面覆盖、日期数字本地化及测试验收结果，同时说明 API 和业务契约未改变。

#### 3.3 Web 验收与证据

- 使用隔离浏览器分别以默认中文和英文访问全部可发现页面；验收范围为第 2.1 节的 10 个页面，以及可从页面触发的模态框、页签、筛选、分页、空状态、成功/失败状态和确认提示。
- 每种语言都必须验证共享导航、当前页面保持、刷新与跨页持久化、系统说明来源、日期数字格式及应用自有文案无中英文混用。
- 频道详情和下载预览等参数化页面必须使用受控本地测试数据访问真实路由；动态状态与错误优先使用本地夹具或现有 API 状态，不依赖真实外部平台。
- 验收证据必须逐页记录语言、路由、检查状态和结果；失败时记录可复现现象，既定阻塞或排除项必须写明原因，不能记为通过。
- 真实 YouTube/Bilibili 等外部平台交互、敏感 Cookie 原文操作和永久删除继续作为既定排除项，不为获得验收证据而执行；其余本地可验证流程不得以该排除项跳过。

## 非功能需求

### 性能与依赖

- 语言解析和翻译查找必须在应用进程或浏览器本地完成，切换语言除重新加载当前页面及其正常数据请求外，不得产生翻译服务网络请求。
- 不增加第三方国际化依赖、构建服务或运行时后台任务；使用 Node.js、EJS 和浏览器原生能力完成两种固定语言的选择与格式化。
- 翻译能力不得改变现有分页大小、请求数量、任务并发、调度频率或下载性能边界。

### 兼容性与可靠性

- 当前中文界面的业务语义、交互结果和所有持久化数据必须保持兼容；已有书签和带查询参数的页面地址继续有效。
- 现有 API 客户端不需要发送语言参数，也不得因语言 Cookie 得到不同结构或不同业务值的响应。
- 同一请求内的服务端 HTML、客户端翻译目录和格式化语言必须一致，避免首屏中文后动态区域变英文等混合状态。
- 无效或缺失语言值必须确定性回到中文；缺失翻译属于开发错误，不能通过运行时猜测或跨语言 fallback 隐藏。

### 安全

- 每次读取语言 Cookie 都必须按精确白名单校验，只把 `zh-CN` 或 `en` 用于翻译选择和 `<html lang>`；不得把原始 Cookie 值直接插入 HTML、文件路径、模块路径或可执行内容。
- 语言 Cookie 不包含身份或敏感业务数据，不得与 Netscape 授权 Cookie 混用，也不得削弱现有同源校验、输出转义、凭据脱敏和可信内网部署边界。
- 翻译参数中的用户输入、标题、路径和第三方错误必须继续通过安全文本方式输出，不得因插值改为不转义 HTML。

### 可访问性

- 语言切换入口必须可通过键盘操作，并具有可理解的当前状态；现有标题层级、表单标签、表格语义、焦点行为和移动端菜单行为不得退化。
- `aria-label`、视觉隐藏标签及其他辅助功能文案必须随当前语言完整切换，不能只翻译可见文本。

### 可观测性与错误处理

- 无效或缺失语言 Cookie 是已定义的中文默认路径，不产生用户可见错误，也不需要新增日志或指标。
- 翻译键缺失、双语键集合不一致和 README 排除标记损坏必须在测试或启动边界明确暴露，不能静默返回空文案或混合语言。
- 本版不新增语言使用统计、用户跟踪、遥测、远端翻译失败处理或其他与两种固定语言无关的可观测性设施。
