# VidHarbor v0.1 产品需求文档

## 功能概述

VidHarbor v0.1 是一个面向可信内网部署的单用户、自托管 YouTube 视频管理 MVP。用户在配置全局下载根目录及可选的命名代理后，可以保存频道并人工同步最近 1、3、6 或 12 个月的普通视频；首次同步只建立历史列表，不产生提醒，后续检查发现的新视频在站内提醒，由用户决定是否下载。系统同时支持粘贴单个视频地址直接下载，并使用 SQLite 持久化配置、频道、视频、提醒和下载状态，使容器重启后能够恢复展示。

## 用户故事

1. 作为内网中的唯一用户，我希望配置统一的下载根目录，以便所有下载文件按固定位置归档。
2. 作为需要访问不同视频平台的用户，我希望维护命名代理，并在频道或单视频下载时选择某个代理或直连，以便明确控制每次访问所用的网络路径。
3. 作为频道关注者，我希望粘贴频道地址后由系统识别受支持的平台，并为频道设置自定义名称和检查间隔，以便集中管理不同来源的频道。
4. 作为首次添加频道的用户，我希望人工选择最长一年的历史范围进行同步，但不收到历史视频提醒，以免首次同步产生大量噪音。
5. 作为持续关注频道的用户，我希望系统按计划检查更新，并在站内提示后续发布的新普通视频，以便由我选择是否下载。
6. 作为下载用户，我希望从频道视频列表中选择视频下载，并按自定义频道名称和发布年份归档，以便在文件系统中直接定位内容。
7. 作为临时下载用户，我希望粘贴一个受支持的单视频地址并选择代理或直连后直接下载，而不必先关注频道。
8. 作为自托管服务用户，我希望服务重启后仍能看到已有配置、频道、视频、提醒及下载记录，以免运行状态丢失。

## 功能详细说明

### 1. 全局下载根目录配置

- 系统提供全局下载根目录配置，作为频道视频和单视频下载的统一根路径。
- 下载根目录是发起下载的必备配置；未配置、为空、目录不可访问或不可写时，系统必须明确报错并阻止下载。
- 本版只有一个全局下载根目录，不提供按用户划分的目录，也不引入多个存储后端。
- 系统不得在根目录不可用时静默改用其他目录。

### 2. 命名代理与直连选择

- 用户可以保存多个命名代理配置；代理的具体字段格式由后续技术设计依据 yt-dlp 的单一受支持格式确定，不在本 PRD 中增加字段别名或多格式兼容。
- 代理配置是可选项；即使没有代理，频道访问和单视频下载仍可明确选择直连。
- 添加频道时需选择一个已存在的命名代理或直连；单视频下载时同样需选择一个已存在的命名代理或直连。
- 代理不存在、配置无效或连接失败时，本次操作必须显式失败并展示原因，不得自动切换到其他代理或直连。
- 本版不实现代理池、自动轮换、健康选路或失败后的自动 fallback。

### 3. 频道添加、平台识别与频道配置

- 添加频道的必填输入为频道地址和自定义频道名称；网络路径为一个命名代理或直连。
- 系统只接受技术设计列出的固定 YouTube 频道地址，不宣称支持 yt-dlp 可处理的其他站点。
- 地址无法识别、平台不在支持清单、地址不是频道地址或自定义名称为空时，保存失败并向用户展示明确错误。保存频道只持久化配置，不访问外部网络。
- 频道使用全局检查间隔；用户可以为单个频道设置覆盖值。未设置覆盖值时只使用全局值，不增加其他优先级来源。
- 频道自定义名称用于界面展示和下载目录。名称对应的文件系统合法性校验规则需在技术设计中固定；校验不通过时必须拒绝保存，不能静默改名。
- 同一频道不得重复添加，频道地址不支持修改或迁移。删除频道时，如果存在下载记录或正在执行检查则拒绝；否则删除频道及其视频、提醒和检查记录，不删除磁盘文件。

### 4. 人工首次同步普通视频

- 频道保存后处于“待首次同步”，不会自动调用 yt-dlp。用户手动触发首次同步，并从最近 1、3、6、12 个月四个固定范围中选择一个，默认 1 个月且最大 1 年。
- 首次同步请求受理后立即返回，频道状态变为“首次同步中”，抓取在后台继续执行；成功后写入所选范围内的普通视频并进入定时检查，失败时保留频道和失败原因，允许用户重新触发。服务重启会把未完成的首次同步恢复为失败状态。
- “普通视频”明确排除 Shorts、直播和直播回放；这些内容不进入历史列表，也不产生后续提醒。
- 历史列表至少展示支持用户识别和选择视频所必需的信息：视频标题、发布日期及原始地址。其他元数据不属于本版已确认契约。
- 首次同步得到的视频一律视为历史数据，只展示、不生成站内更新提醒，也不自动下载。
- 抓取失败必须使本次首次同步显式失败并展示原因；所选范围内确实没有普通视频时允许同步成功并保存空历史列表。
- 最近一年的边界按视频发布日期判断；具体时区和边界日计算规则需在技术设计中固定，并在全系统保持一致。

### 5. 定时检查与站内更新提醒

- 系统按全局检查间隔检查所有频道；配置了频道覆盖值的频道只使用其覆盖值。
- 后续检查仅把首次同步之后新发现的普通视频作为更新；Shorts、直播和直播回放继续排除。
- 新视频写入频道视频列表并在站内形成可见提醒，提醒中必须能定位到对应频道和视频，并允许用户进入选择下载流程。
- 新视频只提醒，不自动下载。
- 单个频道检查失败时记录并展示该频道本次失败，不得把失败解释为“没有更新”，也不得阻断其他频道按各自计划检查。
- 用户可以标记单条提醒或全部提醒为已读。本版不实现外部推送、提醒删除或提醒保留期限策略。

### 6. 频道视频选择与下载

- 用户可以从频道视频列表中选择一个或多个视频并发起下载；系统仅下载用户明确选择的视频。
- 下载使用该频道配置的命名代理或直连，不进行自动代理切换。
- 系统通过 yt-dlp 获取媒体，并在需要合并或转码时调用 FFmpeg；用户只能提交界面中已经固定的媒体类型、格式、清晰度、编码、字幕、缩略图、章节、时间范围、文件名预设和目标子目录字段。
- 下载状态固定为 `pending`、`downloading`、`running`、`completed`、`failed`、`canceled`、`interrupted`；失败或中断原因必须持久化并对用户可见。
- 只有 yt-dlp/FFmpeg 正常完成且目标文件已写入时才能标记为 `completed`；进程错误、代理错误、目标目录错误或文件写入错误均标记为 `failed`，不得吞错或标记成功。
- 用户可以取消活动任务，并手工重试 `failed`、`canceled` 或 `interrupted` 任务。本版不实现自动重试、暂停、断点续传或失败后自动改用直连。

### 7. 频道视频目录归档

- 频道视频写入：`<全局下载根目录>/<频道自定义名称>/<发布年份>/`。
- 发布年份来自视频发布日期，必须与列表中使用的发布日期口径一致。
- 系统不得在缺少频道自定义名称或发布日期时猜测目录值；缺少必要信息时下载失败并明确报错。
- 最终文件名、同名文件处理、已存在文件处理和非法文件名字符转换规则在原始需求中未定义，必须在技术设计与实现前形成单一明确契约，不得加入多套 fallback。

### 8. 单视频地址直接下载

- 用户可以输入一个单视频地址，选择一个已存在的命名代理或直连，并发起下载。
- 输入地址必须是本版明确支持的视频地址；无法识别、平台不受支持、地址不是单视频或视频不可访问时，操作显式失败。
- 单视频下载不要求先添加对应频道，也不因此自动创建频道或关注关系。
- 单视频下载写入全局下载根目录。原始需求未定义其子目录与文件名规则，技术设计与实现前必须固定单一规则，不能借用或猜测频道目录信息。
- 单视频下载沿用相同的下载状态和错误可见性要求。

### 9. SQLite 持久化与重启恢复

- 系统使用 SQLite 持久化全局设置、命名代理、频道配置、频道视频、站内提醒及下载记录。
- 容器重启后，系统必须恢复上述持久化数据及下载记录的最后状态，页面刷新后可继续查看。
- 重启前已为 `completed` 或 `failed` 的记录保持原状态。
- 重启时处于 `pending`、`downloading` 或 `running` 的任务统一恢复为 `interrupted`，不得静默标记完成、自动续传或自动重试。
- SQLite 数据文件和下载根目录必须通过容器持久化挂载保留；容器重建不得以临时容器文件系统作为唯一存储位置。

### 10. MVP 范围与明确排除项

- 部署模型为单用户、无登录、可信内网内的单容器服务。
- 前端技术限定为 Bootstrap 5 与 Sass；服务端使用 Node.js 与 TypeScript；数据存储使用 SQLite；下载工具使用 yt-dlp 与 FFmpeg。
- 本版明确不包含：多用户、登录与权限系统、Shorts、直播、直播回放、外部推送、自动下载频道更新、代理池、媒体转码预览副本、频道地址迁移，以及对所有 yt-dlp 站点的频道支持承诺。
- 未在本 PRD 中确认的输入格式、字段、状态、事件、兼容方式和自动 fallback 均不属于 v0.1 范围。

## 非功能需求

### 性能与资源

- 本版面向单用户内网部署，不设未经验证的吞吐量、响应时间或并发下载指标。
- 定时检查单个频道失败不得阻塞其他频道；下载等长耗时操作不得让管理页面失去基本查询能力。
- yt-dlp 与 FFmpeg 的进程退出结果必须被服务端准确接收，不能仅因进程已启动就视为下载成功。

### 兼容性与部署

- 应用、Node.js 运行时、yt-dlp 与 FFmpeg 必须封装在一个容器中运行。
- SQLite 数据文件与下载根目录通过外部持久化挂载提供；部署文档必须明确两者的挂载位置。
- 浏览器兼容范围、CPU 架构、操作系统和具体受支持平台清单当前未确认，不在本 PRD 中扩展承诺。

### 安全

- 系统没有登录和权限控制，只能部署在访问边界已由用户控制的可信内网中；不得把“无登录”描述为可安全暴露到公网。
- 用户提交的频道地址、视频地址、自定义频道名称、下载根目录和代理配置必须在使用前按固定契约校验。
- 传给 yt-dlp、FFmpeg 和文件系统的值必须作为参数处理，禁止拼接为可执行 shell 命令；目录路径必须受配置的下载根目录约束，防止路径穿越。
- 日志与错误页面不得无必要地展示完整代理凭据。

### 可观测性与错误处理

- 频道首次同步、定时检查和每次下载必须记录开始时间、结果及失败原因；下载记录还需保留当前状态。
- 用户界面必须区分“成功但没有更新”和“检查失败”，区分“尚未下载”“下载中”“下载完成”“下载失败”。
- 不支持的平台、无效地址、必要字段缺失、代理失败、下载工具失败、目录不可写和持久化失败均需显式报错；不得静默忽略、静默返回或猜测式兜底。
- 错误应在能确定业务结果的边界处理：单频道检查错误不终止其他频道检查，单下载任务错误不把其他独立任务标记失败；SQLite 无法读写等系统级错误应中断依赖持久化的操作。

### 验收与测试边界

- 测试必须覆盖本 PRD 的正向场景，以及不支持的平台、非频道/非单视频地址、缺失必填字段、不可写目录、无效代理、Shorts/直播/直播回放排除、下载工具失败和重启恢复等负向边界。
- 测试必须证明首次历史视频不提醒、后续新视频只提醒不自动下载、频道覆盖间隔优先于全局间隔、代理失败不自动切直连，以及目录归档遵循固定路径。
- 未确认格式、未确认状态、未确认平台和未确认自动行为不得通过宽松解析或 fallback 被测试为受支持。
