# VidHarbor

VidHarbor 是部署在可信内网中的单用户视频管理工具，用来关注 YouTube 和 Bilibili 频道、发现新视频、接收站内提醒，并将用户明确选择的视频归档到本地。

项目的关键特征是：单用户、无登录、本地存储、由用户决定下载内容。

## 当前功能

- 关注 YouTube 与 Bilibili 频道，人工同步历史视频，并按计划检查新视频。
- 通过站内提醒发现更新；历史同步和后续检查都不会自动下载。
- 从频道视频列表批量创建任务，或直接提交受支持的单视频地址。
- 查看下载进度、失败原因与归档信息，并取消、重试、预览、保存或删除任务。
- 配置下载目录、检查间隔、下载并发数和命名代理。
- 通过只读 SQL 浏览当前 SQLite 数据，辅助本地排查和核对。

## 项目边界

VidHarbor 不会自动决定下载内容。频道检查只负责建立视频记录和提醒，必须由用户在频道或提醒页面找到视频后明确发起下载。也可以绕过频道，直接提交一个受支持的单视频地址。

> **只能部署在可信内网：** 项目没有登录、用户隔离和权限系统。接口的同源校验不是身份认证，服务端口不能直接暴露到公网。

## 从配置到归档

1. **完成配置：** 设置下载根目录、全局检查间隔和下载并发数；需要代理时先创建命名代理。
2. **添加频道：** 提交受支持的 YouTube 或 Bilibili 频道地址、自定义名称、网络路径，以及可选的频道检查间隔。
3. **首次同步：** 手动选择最近 1、3、6 或 12 个月。历史视频只进入列表，不生成提醒，也不自动下载。
4. **发现更新：** 后台按检查间隔查询最近 1 个月；数据库中没有出现过的视频会进入频道列表并生成提醒。
5. **选择下载：** 用户从频道视频列表选择内容，或在下载页面提交单视频地址。
6. **本地归档：** 主媒体成功后任务即完成，文件归档到以下载 ID 命名的目录。

## 支持范围

| 能力 | 当前支持 | 明确限制 |
| --- | --- | --- |
| 频道订阅 | YouTube 的 `/channel/<id>` 与 `/@handle`；Bilibili 的 `https://space.bilibili.com/<数字UID>` | YouTube 不包含 Shorts、直播和直播回放；Bilibili 只包含 UP 主普通视频投稿，不包含动态、直播、番剧、收藏夹、合集入口和音频 |
| 直接下载 | 已验证 YouTube、Bilibili、Vimeo、X、Facebook 公开单视频或 Reel；抖音公开单视频地址可提交 | 不展开主页、播放列表或合集；资源必须能解析为恰好一个条目；不支持私密或需要登录的内容 |
| Bilibili | 普通视频；多 P 可用 `?p=序号` 指定 | 未指定分 P 时选择第一 P |
| X | 具体视频地址 | 一帖多视频必须带 `/video/序号` |
| Facebook | 公开单视频与公开 Reel | 不支持私密、好友可见、年龄限制或要求登录的内容 |
| 抖音 | `https://www.douyin.com/video/<数字ID>` 公开单视频 | yt-dlp 可能要求 fresh cookies；当前项目没有 cookies 来源，因此能否成功取决于出口网络和平台风控，不支持用户主页或合集 |

直接下载的资源必须提供非空 `extractor_key`、标题以及可安全用于归档文件名的 ID，ID 只能包含字母、数字、下划线和连字符。HTTP 地址、缺少必要元数据的资源以及需要但未提供登录信息的资源会明确失败。

## 频道如何发现视频

### 首次同步

范围由用户选择，只接受最近 1、3、6 或 12 个月。符合条件的视频标记为历史数据，因此不会产生“新视频”提醒。所选范围内没有普通视频时允许同步成功。

### 后续检查

范围固定为检查开始时间之前最近 1 个自然月，没有用户选项，日期边界当天包含在查询范围内。

调度器每分钟判断频道是否到期。频道设置了覆盖间隔时只使用频道值，否则使用全局间隔；暂停的频道不检查。检查时 yt-dlp 按发布日期边界读取普通视频，系统再用平台视频 ID 与数据库比较，只有未保存过的视频才建立记录和提醒。

新视频通常会在下一次计划检查完成后出现，因此发现延迟取决于检查间隔、最多约一分钟的调度等待，以及目标站点和网络带来的实际检查耗时。用户也可以点击“立即检查”。

## 下载、成功条件与文件

下载支持视频或音频、格式、质量、编码、字幕、章节切分和时间裁剪。探测与实际下载都按单项资源执行，不会展开播放列表。

- **成功条件：** 主媒体文件成功并通过校验，任务就算成功；新任务同时保存主媒体文件大小。
- **缩略图：** 每个任务自动尝试保存；缩略图缺失或下载失败不影响主媒体成功。
- **目录结构：** 新任务归档到 `<下载根目录>/<下载ID>/`，目录可同时包含主媒体、缩略图、字幕和章节文件。
- **删除行为：** 删除新布局的已完成任务会删除整个下载 ID 目录和数据库记录；升级前的旧记录保持原文件路径。

下载不会自动重试或续传。失败、取消和服务重启后中断的任务可由用户手动重试。同平台、同视频 ID 已有等待、运行中或已完成记录时，新的提交会直接拒绝且不创建重复任务；失败、取消或中断后允许用户明确重建。下载记录保存并展示来源平台。下载页面固定分为“已完成”“下载中”“失败”三个视图并默认打开“已完成”；成功记录只显示缩略图、标题、总时长、文件大小、完成时间、存储路径和操作。升级前无法可靠取得历史大小的旧记录显示“—”。

## 页面说明

| 页面 | 用途 |
| --- | --- |
| 总览 | 查看频道最近检查状态、未读提醒数、运行中任务和失败或中断任务数量 |
| 下载 | 新建单视频下载，分别查看已完成、下载中和失败任务，取消、重试、预览、保存或永久删除文件 |
| 频道 | 新增和配置 YouTube 或 Bilibili 频道，触发首次同步、立即检查、暂停、恢复或删除频道 |
| 频道详情 | 筛选和选择视频下载，查看最新下载状态、文件大小、完成时间、失败原因与文件操作，并查看首次同步和后续检查记录 |
| 提醒 | 查看后续检查发现的新视频，打开原始视频或对应频道，并标记单条或全部提醒为已读 |
| 配置 | 设置下载根目录、全局检查间隔、下载并发数，以及管理 HTTP、HTTPS 或 SOCKS5 代理 |

| 说明 | 展示本 README；侧边栏最底部的“说明”入口指向 `/guide` |

下载、频道、频道视频、频道检查记录和提醒列表均由服务端分页，每页固定 20 条。搜索和状态筛选先在服务端应用，再对结果分页。“全部标记已读”作用于全部提醒，不受当前页限制。

## 启动与首次配置

项目要求 Docker 与 Docker Compose，并固定 Node.js、yt-dlp、FFmpeg 和系统包版本。

```sh
docker compose up --build -d
docker compose ps
```

Compose 默认映射到 `http://localhost:3002`。容器健康检查请求总览页 `GET /`；健康只表示进程能够提供页面，不代表 YouTube、Bilibili 或代理可达。

首次使用顺序：

1. 启动服务并确认容器健康。
2. 在“配置”中设置下载根目录、全局检查间隔和下载并发数。
3. 如有需要，创建 HTTP、HTTPS 或 SOCKS5 命名代理。
4. 添加 YouTube 或 Bilibili 频道并设置唯一的自定义名称。
5. 手工选择 1、3、6 或 12 个月执行首次同步。
6. 后续从提醒或频道页面选择视频下载，也可以在下载页面提交单视频地址。

选择直连时不会自动切换到代理，指定代理失败时也不会回退到直连。项目没有 cookies 来源、自动代理选择或代理池。

## 数据与运维

两个持久化挂载缺一不可：

- `/data`：保存 SQLite 数据库，默认文件为 `/data/vidharbor.db`，其中包含频道、视频、提醒、下载状态、配置以及可能存在的明文代理凭据。
- `/downloads`：保存下载归档。配置的下载根目录必须是该挂载本身或它已经存在的真实子目录。

项目只支持单容器、单实例运行。进程内调度器和 FIFO 下载队列没有多副本协调能力。备份 SQLite 前应停止容器，数据库和下载目录都必须放在持久化挂载中。

“数据库”页面会展示查询结果，包括代理表中可能存在的明文凭据。它只拒绝写 SQL，不提供字段脱敏、查询结果权限控制或资源隔离，因此同样只能在可信内网使用。

若使用 bind mount，需预先创建宿主机目录，并确认容器用户具有读取、写入和进入权限。持续监控 `/downloads` 的容量、权限和挂载状态。

## 失败如何处理

- 频道检查失败会记录失败原因，不会伪装成“没有更新”，也不会阻断其他频道。
- 指定代理失败时不会自动切换为直连；选择直连时也不会自动寻找代理。
- 下载失败不会污染其他任务，也不会覆盖已存在的归档目录或文件。
- 服务重启时，未完成下载标记为“已中断”，未完成首次同步标记为“失败”，都不会自动重试。
- 文件缺失或删除失败时保留数据库记录并明确报错，避免出现记录已删但文件状态不明。
- 磁盘耗尽、挂载丢失、目标已存在、零字节输出、路径越界或 yt-dlp/FFmpeg 非零退出都会使对应任务明确失败。

当前不提供：自动下载、自动重试、外部推送、提醒删除、频道地址修改、cookies 配置、代理池、自动代理选择和公网安全访问。

## 本地验证

默认测试完全离线，使用临时 SQLite、临时下载目录以及假 yt-dlp/FFmpeg，不访问公网，也不使用真实代理凭据。

```sh
npm ci
npm test
npm run build
```

真实站点冒烟不属于默认测试。升级固定的 yt-dlp、FFmpeg、Node.js 基础镜像或原生依赖前，必须在目标 CPU 架构和实际部署网络中验证 YouTube 与 Bilibili 频道元数据、YouTube、Bilibili、Vimeo、X、Facebook 和抖音单项资源、需要 FFmpeg 合并的下载、原子归档，以及代理和直连路径。
